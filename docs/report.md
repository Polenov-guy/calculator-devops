# Развёртывание калькулятора с CI/CD и мониторингом

## Реализованный процесс

Исходники приложения хранятся в GitHub. CI запускает тесты и компилирует Go-приложение со встроенным HTML/CSS/JS. Бинарник, build-info и SHA256 сохраняются как самостоятельный tar.gz artifact. Следующий job скачивает артефакт, проверяет контрольные суммы и копирует бинарник в runtime Docker image. Образ тестируется с persistent SQLite volume и публикуется в GHCR с тегом commit SHA. Сервер получает immutable digest и исходный bundle инфраструктуры, скачивает образ и обновляет Docker Compose stack.

После обновления проверяются readiness, версия и серверное вычисление с записью/чтением истории. Ошибка обновления вызывает попытку отката на предыдущий образ и его конфигурацию. Перед обновлением снимается SQLite online snapshot. Именованные volumes сохраняют историю вычислений, Prometheus TSDB и Grafana.

Мониторинг: Node Exporter для ресурсов сервера, cAdvisor для контейнеров, Blackbox для HTTP readiness, собственные counters для открытий страницы и вычислений. Grafana dashboard и Prometheus datasource provisioned из Git. Метрика посещений — число открытий главной страницы за скользящий час, не уникальные пользователи.

## Ограничения

Одна VM, возможен короткий перерыв при обновлении. Backup остаётся на том же VPS, пока не скачан отдельно. Blackbox проверяет приложение из сети VPS. В базовой поставке HTTP по IP; HTTPS требует домена и reverse proxy. Runtime data сохранены в volumes, но не защищены от удаления самого VPS. Actions и container base tags фиксированы версиями, не immutable digest. Версия схемы SQLite одна, миграции не требуются. Доставка alert-уведомлений не настроена.
